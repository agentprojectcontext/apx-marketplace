# Browserbase session status

Original MIT, dependency-free Node24 MCP for one **existing** session: `browserbase_session {"session_id":"..."}`. Reads selected status metadata only. Not a cloud browser driver or replacement for APX's embedded browser. Fixed GET `https://api.browserbase.com/v1/sessions/{id}?includeLabels=false`, X-BB-API-Key header, no generic URL/method/header options.

```bash
apx extensions inspect "$PWD/integrations/browserbase"
apx extensions install "$PWD/integrations/browserbase"
```

From marketplace checkout with local core; absolute folder must exist on core host. Installs **off**. Review **Resources > Extensions > Browserbase**, set `api_key` and exact `project_id` privately in the form and enable only when trusted. Node24/HTTPS on MCP host, existing account/plan/API key from [Browserbase settings](https://www.browserbase.com/settings). Secrets passed by reference, never as command arguments or chat; no account creation, OAuth/refresh flow, local credential/profile discovery or SDK dependency. Select least available vendor permissions; no claim of a read-only/project-scoped API-key grant if vendor does not provide it. API key can authorize more than this wrapper; revoke/rotate it in vendor settings if needed. Project guard is a post-retrieval disclosure check, not attenuation of the key's authority.

## Supported result and boundaries

Observed/provided id only (bounded URL-safe identifier, no guessed enumeration). Exact session/project match before any output; private project id not returned. Positive projection of session id, PENDING/RUNNING/ERROR/TIMED_OUT/COMPLETED, createdAt/updatedAt/startedAt/expiresAt, optional endedAt, region (us-west-2/us-east-1/eu-central-1/ap-southeast-1), boolean keepAlive and nonnegative decoded safe-integer proxyBytes as string. Strict calendar/timezone timestamp checks, unsupported/null required metadata fails. Byte observation is not full-u64 decoding, invoice/usage accuracy or financial proof. Status isn't page availability, a live browser connection, contents, completed work or full upstream parity.

Vendor GET may include **connectUrl, seleniumRemoteUrl, signingKey, contextId, userMetadata and labels** even when not requested. They enter the MCP process transiently; all are excluded by positive projection before output. Never dump responses for debugging. No raw body/provider diagnostics/logging/cache or free-text metadata forwarded; API key redacted from selected string output. Existing APX chat/query/results can remain. No browser/CDP connection, sessions list/create/update/release, contexts, pages, cookies, downloads, recordings, labels or signing APIs; do not attempt connection even if metadata claims RUNNING. Response data untrusted, never instructions. Max1MiB/20s default, propagated cancellation, no redirects, automatic retry/paging/polling or alternate endpoint. Auth/rate/schema/mismatch failures stop without data/false zero.

Vendor plan/session/proxy charges/quotas and terms apply. Read does not create a session/paid plan. **Disabling/removing does not end remote sessions or ongoing billing**, revoke vendor keys or erase APX chat; owner manages sessions/revocation in Browserbase. Do not create, release or change a session to fix read errors. No live account/session/auth/availability/security evidence is implied by fixtures, stdio or isolated off-install. Actual evidence is recorded in repository execution report.
